perf study 8 — instruction-attributed block decomposition, ARCHON D48X PGO vs SF18
================================================================================
Instrument: perf record -e instructions:u -c 500000 (every sample == 500,000
retired user instructions, so per-symbol sample share IS per-symbol instruction
share).  Both engines on their NATIVE AVX-512 path (ARCHON target-cpu=native on
a 7700X; the official stockfish18 binary is x86-64-vnni512) — this is NOT the
AVX2-twin callgrind path studies 2/3/7 used for schedule counts.
Workload: bench 16 1 300000 tools/nnue/calib/wl50.fens nodes
Nodes: ARCHON 15,001,846 / SF18 15,010,238 (0.06% apart)
Totals: ARCHON 7116.6 instructions/node, SF18 4330.6 (ratio 1.6433, spread 0.0000%)

Raw flat profiles: flat-ours-d48x-instructions.txt, flat-sf18-instructions.txt
Raw branch profiles: flat-ours-d48x-branches.txt, flat-sf18-branches.txt

The 2.02x branch ratio — flagged in the mandate as the least explained number in
the chain — is an EVAL-layer number (3.17x), not a shell number (1.31x).  The
single largest identified contributor was one un-hoistable bounds check in
`l1_dot`'s group loop: removing it took 5.25% of ALL engine branches
(4.076 G -> 3.862 G on an identical 5,001,629-node tree).

--------------------------------------------------------------------------------
`SotaHead::forward_into` phase split (16.55% of engine, from annot-forward_into.txt)
--------------------------------------------------------------------------------
phase                             % of symbol   % of engine
activate (pairwise FT merge)          29.84         4.94
find_nnz (vptestmd/vpcompressw)        4.53         0.75
l1_dot (sparse int8 matmul)           37.30         6.17
l1_dequant                             0.26         0.04
l2_tail (16->32) + l3 (32->1)         13.03         2.16
skip_dot (DENSE 1280 u8 x f32)        15.09         2.50

Derived: the l1_dot group loop is 11 static instructions and costs 6.17% of the
engine => ~1123 instructions per eval => ~100 active groups per eval out of 320
=> **FT group density ~31%**, and evals/node = 0.366.  The `find_nnz` doc
comment claiming "~85-95% are zero" is wrong for the D48X net by a factor of 3,
and it is what made a sparse `skip_dot` look attractive (it is not: at 31% group
density the 16-element block occupancy is 1-0.69^4 = 77%).

memset-vec-unaligned-erms.S   ~0.10%

perf cannot symbolise glibc's ifunc-resolved bodies, so this block appears in a
flat profile as bare `0x189e4d`-ish addresses with no caller and was recorded as
"absent" by study 7.  Call sites (scripts/libcalls8.py over objdump -d):
  2560 B memcpy  x2  Worker::do_move
  2560 B memcpy  x1  ThreatContext::at_full            (empty-delta span copy)
  2560 B memcpy  x1  HalfkaContext::current_full       (empty-dirty span copy)
  2560 B memmove x1  HalfkaContext::finny_refresh_into (cache -> stack)
  2560 B memcpy  x1  HalfkaContext::finny_refresh_into
  2560 B memcpy  x2  ThreatContext::refresh
  2560 B memcpy  x2  ThreatContext::apply_at           (refresh_threat by-value return)
  1280 B memset  x1  SotaHead::forward_into            (the dead `[0u8; L1]` init)
2560 B == 2 perspectives x 1280 i16 == one accumulator pair at D48X.
