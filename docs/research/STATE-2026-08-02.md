## The finding that reframed the project

**Our labels point the wrong way.** Blending 40 % of a Stockfish net into the
training target gained **+30.42 ± 11.02** while the label-heldout loss **rose
monotonically**. If labels were merely noisy, moving off them would COST Elo;
gaining means they are **biased**. Label quality is the binding constraint.

Corroborating: SF's net in OUR search at equal nodes is **+90.7**, on an
identical 83,248-input space, while our accumulator is 1.25× *larger*.

**Consequence:** the data program is now generate-our-own. Tools built and
validated (`tools/ops/data/`, 4-stage pipeline); **nothing is generating** —
awaiting the owner's go. Operating point measured: oracle `stockfish-eca43a97`
@10k nodes, 50/30/20 self/SF18/SF16, 80 positions/game.

## Standing lessons paid for in this session

1. **Account for speed.** A smaller net can only lose at equal nodes — cheaper
   nodes are its entire case. Report equal-time; label fixed-node as the
   per-node component only.
2. **Loss does not predict Elo.** Twice, in opposite directions: the teacher net
   gained +30 while heldout ROSE; the HalfKA-only net's heldout FELL smoothly
   the whole way to −212.
3. **Silent failures dominate.** fastchess reports 0 games and exits 0 on an
   engine/net arch mismatch, and on a malformed `-each`. Verify the payload,
   never the unit state.
4. **Defaults rot.** `ckptreaper` scoped to one dir stopped covering the project
   when a new run started; a spec copied for a new arch inherited `out=` and
   `net_id=` from its parent.
5. **Pre-register the tie rule.** The scale sweep's leader CHANGED between reads;
   the rule written before the games decided it correctly.
